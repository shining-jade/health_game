# 친구사건형 UI 와이어프레임 초안

이번 단계에서는 코드를 짜기보다, 먼저 **화면 구조 / 정보 우선순위 / 모바일·PC 반응형 원칙**을 명확하게 정리한다.

## 1. 설계 목표

이 UI는 단순히 보기 좋은 화면이 아니라, 아래 4가지를 동시에 만족해야 한다.

1. **추리 진행이 직관적이어야 함**
   - 지금 무슨 사건인지
   - 무엇을 조사했는지
   - 무엇이 아직 불확실한지
   - 다음에 무엇을 확인해야 하는지

2. **교육용으로 정리가 쉬워야 함**
   - 단서 → 추론 → 대응 → 학습 정리 흐름이 명확해야 한다.
   - 게임 속 사건 패널과 메모장이 활동지 문항으로 자연스럽게 이어져야 한다.

3. **모바일과 PC 모두 무리 없이 사용 가능해야 함**
   - PC는 다중 패널 중심
   - 모바일은 탭/오버레이 중심

4. **활동지와 구조가 연결되어야 함**
   - 메모장/사건패널 구조가 활동지 문항과 이어져야 한다.
   - 게임 중 작성할 내용과 게임 후 정리할 내용을 구분해야 한다.

## 2. 전체 정보 구조

친구사건형 UI는 크게 5개 블록으로 나눈다.

1. **상단 바**
2. **상태창**
3. **메인 장면 영역**
4. **사건 패널**
5. **보조 도구 영역**
   - 아이템창
   - 메모장
   - 활동지 힌트/질문 보기

## 3. PC 와이어프레임 구조

PC에서는 **3열 레이아웃**이 가장 적합하다.

### 3.1 기본 배치

```text
┌──────────────────────────────────────────────────────────────┐
│ 상단바: 날짜 / 장소 / 사건명 / 조사기회 / 설정              │
├──────────────┬──────────────────────────────┬───────────────┤
│ 좌측 상태창  │ 중앙 메인 장면/대사/선택지   │ 우측 사건패널 │
│              │                              │ + 도구버튼    │
│              │                              │               │
│              │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 하단 보조영역(선택): 빠른 메모, 최근 단서, 시스템 피드백     │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 상단 바

상단 바는 항상 고정되는 정보 영역이다.

포함 요소:

- 현재 날짜 / D-Day
- 장소
- 현재 사건명
- 조사 기회 또는 진행 단계
- 설정 버튼
- 홈/맵 버튼이 필요할 경우 추가

예시:

```text
시험 2일 전 | 2교시 교실 | 사건: 떨리는 손의 이유 | 조사 2/4 | 설정
```

역할:

- 사용자가 현재 맥락을 잃지 않게 한다.
- 육성 시뮬레이션의 시간감을 유지한다.
- 교사용 시연 시에도 흐름을 명확하게 보여준다.

### 3.3 좌측 상태창

좌측에는 플레이어의 **건강 추리 역량 상태**를 배치한다.

구성안:

- 관찰력
- 판단력
- 공감도
- 대응력
- 건강문해력
- 신뢰도

표시 방식:

- 막대형 또는 작은 육각형 요약
- 각 항목 옆 아이콘 사용
- 숫자보다는 직관적 시각 표현 우선

예시:

```text
[상태]
관찰력     ████░
판단력     █████
공감도     ███░░
대응력     ████░
건강문해력  ███░░
신뢰도     ████░
```

추가 표시 가능 요소:

- 현재 열린 질문 수
- 힌트 사용 여부
- NPC 협조도 변화 알림

설계 포인트:

- 상태창은 숫자 경쟁이 아니라 **문제 해결 태도**를 보여주는 장치여야 한다.
- 너무 상세하게 수치화하지 말고 직관적으로 보여준다.

### 3.4 중앙 메인 장면 영역

이 UI의 핵심이다. 가장 넓어야 하고, 사용자의 시선이 가장 먼저 가야 한다.

포함 요소:

1. 장면 배경
2. NPC/사건 이미지 또는 카드
3. 대사창
4. 선택지
5. 조사 버튼 또는 행동 버튼

기본 구조:

```text
┌──────────────────────────────┐
│ 장면 이미지/배경             │
│ (교실, 보건실, 복도 등)      │
├──────────────────────────────┤
│ [대사창]                     │
│ 지우: 민재가 아까부터 손을   │
│ 계속 떨고 있었어.            │
├──────────────────────────────┤
│ 선택지 1                     │
│ 선택지 2                     │
│ 선택지 3                     │
└──────────────────────────────┘
```

중앙 영역에서 가능한 행동:

- 대화 진행
- 특정 NPC에게 질문
- 현장 조사
- 아이템 사용/확인
- 추론 선택

설계 포인트:

- 텍스트가 너무 길면 안 된다.
- 정보 전달은 우측 패널과 나누고, 중앙은 **행동과 몰입** 중심으로 둔다.
- 선택지는 2~4개 정도로 유지한다.

### 3.5 우측 사건 패널

이 영역은 현재 사건을 구조화해 보여준다.

섹션 구성:

1. 현재 이상 징후
   - 손 떨림
   - 창백함
   - 두근거림

2. 확인된 사실
   - 아침 감기약 복용
   - 오전 편의점 방문

3. 불확실한 점
   - 음료를 몇 번 마셨는가?
   - 전날 수면 시간은?

4. 진행도
   - 단서 3/5
   - 진술 2/4
   - 가설 1/3

예시:

```text
[사건 패널]
이상 징후
- 손 떨림
- 안색 창백
- 집중 저하

확인된 사실
- 아침 감기약 복용
- 쉬는 시간 편의점 방문

불확실한 점
- 음료 반복 섭취 여부
- 수면 부족 정도

진행도
단서 3/5
진술 2/4
가설 1/3
```

설계 포인트:

- 교육적 사고 흐름을 눈에 보이게 한다.
- 플레이어가 “지금 뭘 더 알아내야 하는지” 알 수 있게 한다.

### 3.6 우측 하단 도구 버튼

사건 패널 아래 또는 옆에 빠른 버튼을 둔다.

버튼 구성:

- 아이템창
- 메모장
- 핵심 질문
- 활동지 힌트
- 지금까지 배운 것

예시:

```text
[단서함] [메모장]
[핵심질문] [활동지]
```

### 3.7 하단 보조 영역

선택사항이지만 있으면 좋다.

활용 방안:

- 최근 획득 단서 표시
- 시스템 피드백
- “메모장에 추가됨” 알림
- 활동지에 적어보세요 안내

예시:

```text
새 단서 획득: 편의점 영수증
메모장 업데이트: ‘반복 섭취 가능성’ 추가
```

## 4. 모바일 와이어프레임 구조

모바일은 PC처럼 3열을 유지할 수 없기 때문에 **단일 메인 화면 + 하단 탭 전환형**이 가장 적합하다.

### 4.1 기본 배치

```text
┌────────────────────────────┐
│ 상단바: 날짜 / 사건명 / 메뉴 │
├────────────────────────────┤
│ 장면 이미지/배경            │
├────────────────────────────┤
│ 대사창                      │
│ 선택지                      │
├────────────────────────────┤
│ 하단 탭                     │
│ 상태 | 사건 | 단서 | 메모   │
└────────────────────────────┘
```

### 4.2 상단 바

모바일에서는 정보를 축약해야 한다.

표시 우선순위:

- 사건명
- 현재 날짜 또는 단계
- 메뉴 버튼

예시:

```text
시험 2일 전 | 떨리는 손의 이유 | ☰
```

추가 요소:

- 물음표 버튼: 핵심 질문 보기
- 활동지 버튼: 활동지 힌트 팝업

### 4.3 메인 장면 영역

모바일에서는 중앙이 거의 전부라고 생각해야 한다.

포함 요소:

- 배경/상황 이미지
- 대사창
- 선택지 버튼
- 때때로 조사 가능한 오브젝트 표시

설계 포인트:

- 선택지는 세로 스택으로 배치한다.
- 버튼 크기는 터치 친화적으로 크게 만든다.
- 대사 길이는 2~4줄 단위로 잘라 가독성을 확보한다.

### 4.4 하단 탭 구조

모바일의 핵심이다.

추천 탭 4개:

1. **상태**
2. **사건**
3. **단서**
4. **메모**

역할:

- 상태: 역량 상태 확인
- 사건: 증상/확인된 사실/불확실한 점
- 단서: 아이템창
- 메모: 추론 정리

### 4.5 모바일 상태 탭

```text
[상태]
관찰력     ████░
판단력     █████
공감도     ███░░
대응력     ████░
건강문해력  ███░░
신뢰도     ████░
```

특징:

- PC 좌측 패널의 축약형이다.
- 탭 전환 시 전체 화면 또는 바텀시트로 열린다.

### 4.6 모바일 사건 탭

```text
[사건]
이상 징후
- 손 떨림
- 창백함

확인된 사실
- 아침 감기약 복용
- 오전 편의점 방문

불확실한 점
- 음료 반복 섭취 여부

진행도
단서 3/5
```

특징:

- 스크롤 가능한 카드형 UI로 구성한다.
- 중요한 항목은 상단에 고정한다.

### 4.7 모바일 단서 탭

카드형이 가장 좋다.

```text
[단서]
- 편의점 영수증
- 감기약 봉투
- 메신저 대화
- 복용 메모
```

각 카드를 누르면 다음 행동을 제공한다.

- 상세 보기
- 메모장 추가
- 비교하기

### 4.8 모바일 메모 탭

메모장은 모바일에서 너무 복잡하면 안 된다.

추천 구조:

- 사실
- 의심
- 질문
- 대응
- 배운 점

예시:

```text
[메모 - 사실]
- 민재는 오전과 점심에 음료를 샀다.
- 아침에 감기약을 복용했다.
```

## 5. 공통 컴포넌트 설계

PC/모바일 공통으로 유지해야 할 핵심 컴포넌트다.

### 5.1 단서 카드

카드 정보:

- 제목
- 유형 아이콘
- 획득 위치
- 중요 표시
- 상세 보기 버튼

예시:

```text
[영수증] 물리단서
편의점 / 오전 쉬는 시간
[상세보기] [메모추가]
```

### 5.2 메모 카드

메모장은 긴 자유서술보다 카드형 정리가 더 좋다.

카드 유형:

- 사실
- 가설
- 질문
- 대응
- 배운 점

### 5.3 핵심 질문 박스

항상 사건의 중심 질문을 볼 수 있어야 한다.

예시:

```text
핵심 질문:
민재의 상태를 악화시킨 주요 원인은 무엇일까?
```

배치:

- PC: 우측 사건 패널 상단
- 모바일: 팝업 또는 탭 상단

### 5.4 활동지 연계 버튼

디지털에서 오프라인으로 넘어가는 접점이 필요하다.

버튼 문구 예시:

- 활동지에 핵심 단서 적기
- 내 가설 먼저 써보기
- 생각이 바뀐 이유 기록하기

## 6. 화면 흐름 예시

### 6.1 사건 시작

- 상단 바에 사건명 표시
- 중앙에 이상 상황 등장
- 우측 패널 또는 모바일 탭에 사건 패널 초기화

### 6.2 단서 수집

- 플레이어가 장면 선택
- 단서 카드 획득
- 사건 패널의 확인된 사실 갱신

### 6.3 메모 정리

- 메모장에 사실/가설 자동 또는 수동 추가
- 활동지에 적어볼 항목 힌트 제공

### 6.4 추론 선택

- 원인 조합 선택
- 대응 방식 결정

### 6.5 종료

- 사건 결과 요약
- 학습 정리
- 육각형/역량 변화
- 활동지 마무리 문항 안내

## 7. 반응형 설계 원칙

### PC

- 다중 정보 동시 노출
- 비교와 정리에 유리
- 수업 시연에 적합

### 모바일

- 한 번에 한 작업 중심
- 대화/선택이 가장 우선
- 부가 정보는 탭으로 숨김

### 공통

- 장면 몰입을 해치지 않기
- 텍스트 가독성 최우선
- 버튼과 카드 터치 영역 넉넉하게

## 8. 최종 추천 구조

### PC 추천

- 좌측: 상태창
- 중앙: 장면/대사/선택
- 우측: 사건 패널 + 도구 버튼
- 하단: 피드백/최근 단서

### 모바일 추천

- 상단: 사건 요약
- 중앙: 장면/대사/선택
- 하단: 상태/사건/단서/메모 탭
- 오버레이: 단서 상세/메모 입력/활동지 힌트

## 9. 와이어프레임 우선 확정 항목

다음 단계로 넘어가기 전에 아래 4가지를 확정한다.

1. **상태창 6개 항목**
   - 관찰력 / 판단력 / 공감도 / 대응력 / 건강문해력 / 신뢰도

2. **모바일 하단 탭 4개 구성**
   - 상태 / 사건 / 단서 / 메모

3. **사건 패널의 기본 항목**
   - 이상 징후 / 확인된 사실 / 불확실한 점 / 진행도

4. **메모장 탭 구조**
   - 사실 / 의심 / 핵심 질문 / 대응 / 배운 점

## 10. 다음 단계

다음 단계에서는 이 와이어프레임을 실제 화면 문안 수준으로 구체화한다.

구체화할 항목:

- 버튼 이름
- 패널 제목
- 모바일 탭 라벨
- 사건 시작 화면 문구
- 메모장 기본 안내문
- 단서 획득/메모 추가/활동지 연계 피드백 문구
