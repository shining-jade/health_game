# 교사용 소개 페이지 설계

## 1. 목적

`약, 알고 먹자!` 일반의약품 오남용 예방 시뮬레이션을 수업에 활용하려는 교사가 제작 배경, 게임 구조, 결과 유형, 수업 운영 방법, AI 활용 제작 과정을 한 페이지에서 이해하도록 돕는다.

현재 공개된 학생 게임은 그대로 유지한다. 교사용 소개 페이지는 독립된 정적 페이지로 추가하며, 학생용 안내 페이지는 이번 범위에 포함하지 않는다.

## 2. 성공 기준

- 교사가 페이지를 처음 방문한 뒤 게임의 교육 목적과 활용 시점을 빠르게 이해할 수 있다.
- 시험을 앞둔 7일간의 선택 여정을 실제 게임 구조인 `D-7 → D-5 → D-3 → D-Day`에 맞게 설명한다.
- 8가지 결과 캐릭터를 한눈에 살펴보고 각각의 원본 결과 카드를 크게 볼 수 있다.
- PC, 태블릿, 휴대폰에서 가로 넘침이나 잘림 없이 사용할 수 있다.
- 키보드와 터치 입력 모두로 탭과 이미지 확대 기능을 조작할 수 있다.
- 기존 학생 게임 파일과 기존 자산은 변경하지 않는다.

## 3. 배포 위치와 변경 범위

새 페이지의 공개 경로는 다음과 같다.

```text
https://shining-jade.github.io/health_game/teacher-guide/
```

새로 추가할 파일은 다음 세 개다.

```text
health_game_publish/teacher-guide/index.html
health_game_publish/teacher-guide/styles.css
health_game_publish/teacher-guide/script.js
```

결과 카드 이미지는 복제하지 않고 아래 기존 자산을 상대 경로로 참조한다.

```text
health_game_publish/assets/type-result-cards/
```

다음 기존 파일과 디렉터리는 수정하지 않는다.

- `health_game_publish/index.html`
- 기존 학생 게임 JavaScript와 CSS
- `health_game_publish/assets/` 아래의 기존 파일
- `health_game_publish/약물오남용예방_시뮬레이션_리디자인/`

교사용 페이지에서 학생 게임으로 이동하는 링크만 제공한다. 학생 게임에서 교사용 페이지로 들어오는 링크는 이번 작업에서 추가하지 않는다.

## 4. 정보 구조

### 4.1 상단 소개 영역

- 라벨: `교사용 수업 안내`
- 제목: `약, 알고 먹자!`
- 부제: `일반의약품 오남용 예방 육성 시뮬레이션`
- 짧은 소개: 카페인과 일반의약품을 습관이나 권유가 아닌 성분, 효과, 복용 기준을 이해하고 선택하도록 돕는 활동임을 설명한다.
- 주요 버튼: `게임 체험하기`
  - 연결 대상: `../index.html`
  - 같은 탭에서 이동한다.
- 보조 안내: 현재 페이지는 교사용이며 학생용 안내는 추후 확장 예정임을 명시한다.

### 4.2 탭 내비게이션

다음 네 개 탭을 제공한다.

1. `왜 만들었나요`
2. `7일간의 선택`
3. `결과 캐릭터`
4. `수업 활용 · 제작 이야기`

첫 방문 시 `왜 만들었나요` 탭을 연다. 탭을 바꾸면 URL 해시를 `#motivation`, `#journey`, `#characters`, `#classroom` 중 하나로 갱신한다. 유효한 해시로 직접 방문하거나 새로고침하면 해당 탭을 연다. 알 수 없는 해시는 첫 번째 탭으로 되돌린다.

JavaScript를 사용할 수 없는 환경에서는 모든 탭 패널을 문서 순서대로 표시해 핵심 내용을 읽을 수 있게 한다.

### 4.3 왜 만들었나요

다음 내용을 교사의 관찰과 교육적 문제의식 중심으로 정리한다.

- 학생 책상 위에 쌓이는 고카페인 음료
- 두통, 어지러움, 가슴 답답함과 수면 부족을 호소하는 학생들
- 카페인 음료와 쉽게 구할 수 있는 일반의약품을 더 정확히 알고 섭취할 필요
- “엄마가 줘서”, “병원에서 줘서”가 아니라 복용 이유, 효과, 성분, 용법을 이해하고 선택하기를 바라는 마음

페이지 문구는 학생을 비난하거나 공포를 강조하지 않는다. 일상에서 정보를 확인하고 자기 몸에 맞는 선택을 연습한다는 방향으로 작성한다.

### 4.4 7일간의 선택

“7일간”은 일곱 개의 연속 날짜 화면이 아니라 시험을 7일 앞둔 시점부터 시험 당일까지의 선택 여정을 뜻한다고 명확하게 설명한다.

타임라인은 다음 네 시점으로 구성한다.

- `D-7`: 고카페인 음료 권유, 라벨과 카페인 함량 확인, 피로에 대응하는 선택
- `D-5`: 두통과 진통제, 공복 복용, 복용 간격, 다른 사람의 약을 받는 상황
- `D-3`: 술과 진통제, 성분 중복, SNS 건강 정보, 수면과 시험 준비
- `D-Day`: 핵심 개념 미니퀴즈, 누적 선택 분석, 결과 캐릭터와 육각형 능력치 확인

육성 요소로 다음 여섯 능력치를 소개한다.

- 체력
- 지식
- 카페인 관리
- 컨디션
- 판단력
- 사회성

“무엇을 얻으면 다른 것을 잃을 수도 있다”는 트레이드오프를 핵심 메시지로 사용한다. 하나의 정답을 외우는 게임보다는 선택의 결과를 비교하고 더 안전한 대안을 찾는 활동임을 설명한다.

### 4.5 결과 캐릭터

8개의 결과 유형을 카드 격자로 표시한다.

| 순서 | 이름 | 이미지 |
|---|---|---|
| 1 | 신중한 다람쥐형 | `01_squirrel_self_control_result.png` |
| 2 | 든든한 곰형 | `02_bear_hydration_result.png` |
| 3 | 재빠른 개구리형 | `03_frog_courage_result.png` |
| 4 | 꼼꼼한 부엉이형 | `04_owl_medicine_knowledge_result.png` |
| 5 | 균형 잡힌 토끼형 | `05_rabbit_sleep_result.png` |
| 6 | 꾸준한 거북이형 | `06_turtle_focus_result.png` |
| 7 | 침착한 미어캣형 | `07_meerkat_balance_result.png` |
| 8 | 점검이 필요한 햄스터형 | `08_hamster_caffeine_warning_result.png` |

각 격자 항목은 이름, 작은 미리보기, 한 줄 핵심 특성을 포함한 버튼으로 구현한다. 버튼을 누르면 1200×1500 원본 결과 카드가 확대 모달에 표시된다.

결과 유형은 학생을 좋고 나쁨으로 서열화하지 않는다. 햄스터형 역시 실패 캐릭터가 아니라 카페인 섭취와 복용 습관을 다시 살펴보라는 점검 신호로 설명한다.

### 4.6 수업 활용 · 제작 이야기

수업 활용은 이론 지식을 학습한 뒤 정리하고 실제 상황에 적용하는 단계에 배치한다.

권장 흐름은 다음과 같다.

1. 사전 학습: 카페인, 일반의약품 성분, 용법·용량, 복용 간격, 성분 중복을 학습한다.
2. 개인 체험: 학생이 자신의 캐릭터를 설정하고 상황별 선택을 진행한다.
3. 결과 비교: 결과 캐릭터와 육각형 능력치를 보며 어떤 선택이 영향을 주었는지 확인한다.
4. 모둠 또는 전체 토론: 서로 다른 선택과 결과를 비교하고 더 안전한 대안을 설명한다.
5. 정리: 약을 먹기 전 확인할 기준을 학생 자신의 언어로 정리한다.

제작 과정은 다음 역할 분담으로 설명한다.

- 기획자인 교사: 학생 생활에서 문제를 발견하고 교육 목표, 상황, 선택지, 의학·약학 내용을 설계하고 검토
- 참고 장르: `프린세스메이커`, 모바일 게임 `수업생 키우기` 등 육성 시뮬레이션
- Claude: 초기 게임 구조와 큰 흐름을 구상하는 데 활용
- Codex: 세부 기능 구현, 코드 수정과 검증, 이미지 생성 작업에 활용
- 이미지 생성 도구: 배경, 캐릭터, 결과 카드 등 시각 자료 제작에 활용

AI가 교육 내용을 단독으로 결정한 것으로 표현하지 않는다. 교사가 방향을 정하고 결과를 검토하며 AI 도구가 제작을 보조했다는 관계를 분명히 한다.

## 5. 시각 디자인

### 5.1 방향

- 기존 게임과 연결되는 아이보리 배경, 민트와 복숭아색 포인트를 사용한다.
- 교사용 자료이므로 장식보다 정보 위계와 본문 가독성을 우선한다.
- 결과 카드의 동물 일러스트를 페이지의 핵심 시각 요소로 사용한다.
- 과도한 애니메이션은 사용하지 않는다.

### 5.2 타이포그래피

- 기본 글꼴: `Noto Sans KR`, `Malgun Gothic`, sans-serif 순서의 시스템 대체 글꼴
- 본문 최소 크기: 16px
- 모바일에서도 본문이 15px 미만으로 줄어들지 않게 한다.
- 제목 크기는 `clamp()`를 사용해 화면 크기에 따라 조정한다.
- 본문 줄 간격은 약 1.7로 설정한다.

### 5.3 카드와 패널

- 둥근 모서리, 얕은 그림자, 충분한 내부 여백을 사용한다.
- 텍스트와 배경의 명도 대비는 WCAG AA 수준을 목표로 한다.
- hover만으로 정보를 전달하지 않는다.
- 현재 선택된 탭은 색상뿐 아니라 굵기와 밑줄 또는 테두리로도 구분한다.

## 6. 반응형 동작

### 6.1 데스크톱

- 본문 최대 너비: 약 1100px
- 상단 소개는 텍스트와 장식 이미지를 2열로 배치할 수 있다.
- 결과 캐릭터: 4열
- 7일 여정: 4개 시점을 가로 타임라인으로 표시

### 6.2 태블릿

- 결과 캐릭터: 2열
- 상단 소개와 타임라인은 공간에 따라 1~2열로 전환
- 탭은 한 줄 유지가 어렵다면 자연스럽게 줄바꿈한다.

### 6.3 휴대폰

- 모든 주요 영역을 1열로 표시한다.
- 결과 캐릭터는 화면 폭이 충분하면 2열, 작은 화면에서는 1열로 표시한다.
- 탭 내비게이션은 가로 스크롤을 허용하고 현재 탭이 시야에 들어오도록 한다.
- 버튼의 최소 터치 영역은 44×44px로 한다.
- 모달 이미지는 `max-width`와 `max-height`를 함께 사용해 화면 밖으로 잘리지 않게 한다.
- 페이지와 모달에 불필요한 가로 스크롤이 생기지 않게 한다.

## 7. 상호작용과 접근성

### 7.1 탭

- 탭 버튼은 `role="tab"`, 패널은 `role="tabpanel"`을 사용한다.
- 선택 상태를 `aria-selected`로 알린다.
- 좌우 방향키, Home, End로 탭 간 이동을 지원한다.
- 탭 변경 시 연결된 패널에 불필요하게 포커스를 강제하지 않는다.

### 7.2 결과 카드 확대

- 캐릭터 항목은 실제 `button` 요소로 구현한다.
- 모달은 네이티브 `<dialog>`를 우선 사용한다.
- 닫기 버튼, ESC, 배경 클릭으로 닫을 수 있다.
- 모달이 열리면 닫기 버튼으로 포커스를 이동한다.
- 모달을 닫으면 모달을 열었던 캐릭터 버튼으로 포커스를 돌려준다.
- 각 이미지에 결과 유형명이 포함된 대체 텍스트를 제공한다.
- JavaScript가 없을 때는 미리보기 이미지가 원본 이미지로 연결되는 일반 링크로 동작한다.

### 7.3 동작 감소 설정

`prefers-reduced-motion: reduce` 환경에서는 탭 전환과 모달 애니메이션을 제거한다.

## 8. 데이터와 의존성

페이지는 서버, 데이터베이스, 로그인 또는 외부 JavaScript 프레임워크를 사용하지 않는다.

8개 결과 유형의 이름, 이미지 경로, 한 줄 설명은 `script.js`의 작은 상수 배열에서 관리한다. 탭 본문은 검색과 무자바스크립트 접근성을 위해 HTML에 직접 작성한다.

외부 웹 폰트 요청은 필수 의존성으로 두지 않는다. 로컬 또는 시스템 글꼴이 사용되더라도 레이아웃이 유지되어야 한다.

## 9. 오류 처리와 점진적 향상

- 잘못된 탭 해시는 기본 탭으로 처리한다.
- 결과 이미지 로드에 실패하면 깨진 이미지만 남기지 않고 해당 결과 유형명과 `이미지를 불러오지 못했습니다`라는 안내를 표시한다.
- JavaScript가 실행되지 않아도 모든 설명을 읽고 게임 링크와 원본 결과 이미지 링크를 사용할 수 있어야 한다.
- `<dialog>` 기능을 사용할 수 없는 브라우저에서는 접근성 속성을 가진 일반 오버레이 방식으로 대체한다.

## 10. 검증 계획

### 10.1 정적 검사

- HTML 문법과 내부 ID 중복 여부 확인
- CSS와 JavaScript 구문 오류 확인
- 학생 게임 파일과 기존 자산이 변경되지 않았는지 `git diff`로 확인
- 8개 이미지 상대 경로가 실제 파일과 모두 일치하는지 확인

### 10.2 기능 검사

- 네 개 탭의 마우스, 터치, 키보드 전환 확인
- 각 탭 해시 직접 진입과 새로고침 상태 유지 확인
- 8개 캐릭터 모달 열기와 닫기 확인
- ESC, 배경 클릭, 닫기 버튼, 포커스 복귀 확인
- 게임 체험 버튼이 `../index.html`로 이동하는지 확인
- 이미지 실패 상태를 인위적으로 재현해 안내 문구 확인

### 10.3 브라우저 화면 검사

다음 대표 화면 폭에서 실제 렌더링을 확인한다.

- 휴대폰: 360px, 390px
- 태블릿: 768px
- 데스크톱: 1280px 이상

각 화면에서 다음을 확인한다.

- 가로 넘침 없음
- 탭 글자와 버튼이 겹치지 않음
- 본문과 결과 카드가 잘리지 않음
- 모달 닫기 버튼이 항상 화면 안에 있음
- 텍스트 대비와 포커스 표시가 충분함

## 11. 범위 제외

이번 작업에는 다음을 포함하지 않는다.

- 기존 학생 게임 기능 또는 디자인 변경
- 학생 게임에서 교사용 소개 페이지로 연결하는 링크 추가
- 학생용 소개 페이지 제작
- 관리자 페이지, 학급 데이터 저장 또는 학습 결과 수집
- 새로운 캐릭터나 결과 이미지 생성
- 기존 결과 판정 로직 변경
